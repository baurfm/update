# Changelog

- **v12.27** — New: the Scoop section clears the download cache (`scoop cache rm --all`) after every run, so downloaded installers no longer pile up.
- **v12.26** — Fix: the summary still counted "nothing to do" runs as updates — uv ("Python runtimes", "All uv tools"), Google Cloud SDK, Azure CLI, Android SDK, Chocolatey, pipx, RubyGems, Scoop itself and every .NET global tool showed up as "updated" on every run. Successful steps now check the tool's own "nothing to do" message (`Test-NoOpOutput`, phrases taken from real output), Scoop compares its core version before/after, and .NET tools count only on "successfully updated from version …". UX: the closing box separates skips from tools that aren't installed ("4 skipped · 12 not installed"). Docs: `update -h` description lists all sections instead of the original six.
- **v12.25** — Fix: the temporary Git.Git / Windows Terminal pins never worked — `winget pin add --gated` isn't a valid option and failed with `0x8A150002` (invalid arguments) every time, so Git.Git still failed while Git Bash was open; now a plain pin (`--id … -e`), which excludes the package from `upgrade --all` but keeps explicit upgrades possible. The "already pinned by the user?" check also never matched (it looked for the ID at the start of the line, where `winget pin list` prints the name). Fix: the Windows Terminal self-upgrade protection never fired in practice — it checked `$env:WT_SESSION`, which the elevated child (where winget runs) doesn't inherit; the parent now passes it down (`-InWindowsTerminal`), and both `Microsoft.WindowsTerminal` and `Microsoft.IntelligentTerminal` are covered. Fix: after Ctrl+C in a run started in-process (Scoop shim), every following `update` in that window claimed "Another run is active" — a lock holding the current shell's own PID is now recognised as stale. Fix: the elevated re-launch loaded the user's PowerShell profile (slow, and profile output leaked into the run) — now `-NoProfile`. Fix: the elevated child lost the emoji icons because `WT_SESSION` isn't inherited across elevation — the parent passes its decision down (internal `-Emoji`). New: `-PathSetup On|Off|Status` replaces `-RemoveFromPath`. Fix: `-RemoveFromPath` undid itself on the next normal run (auto-setup re-added the shim and PATH entry) — `Off` now persists via a `.no-path-setup` marker. Fix: the automatic PATH setup also ran during `-DryRun` and in the elevated child process. Fix: with a custom `-LogFile` outside `logs\`, log rotation always failed (`Rename-Item` can't move across folders) and the archive cleanup looked in the wrong folder — archives now live next to the log file. UX: Windows Update without admin is a one-line skip with reason instead of an empty section with "Done 0s" (`Update-Section -SkipReason`). Docs: README rewritten as a short, task-oriented guide; full references moved to `docs/` (tools, parameters, unattended, development) and the version history to this file.
- **v12.24** — New: `-Schedule On|Off|Status` toggles the nightly Scheduled Task without losing its configuration (`Off` disables instead of deleting; `On` registers or re-enables; `Status` shows state, last/next run and the account it runs as).
- **v12.23** — Speed/logging: `Write-Log` used `Add-Content`, measured at ~30 ms per line (provider overhead plus AV/OneDrive scanning each file open) — ~90 s for a 3000-line tlmgr run; now `File.AppendAllText`, and large tool outputs / TeX Live log files are written as one block (`Write-LogBlock`). Logs are now UTF-8 on PS5.1 too (were ANSI, mangling umlauts). Log header with version, PID and elevation state, a marker line per section, exit code at the end. Fix: the elevated re-launch and the self-update re-exec rotated the log again, archiving the first half of the same run (pre-checks, elevation reason) — continuations now append. Reliability: a locked/unwritable log file no longer spams an error per line (one warning, then the run continues); the winget/WSL elevation pre-check jobs have a 120 s timeout (a hanging winget source refresh blocked startup forever); errors outside the per-section handling are logged with their script position via a script-level `trap` and the run continues. UX: summary separates actionable skips from "not installed" tools.
- **v12.22** — New: Windows Update section via PSWindowsUpdate (`-NoWindowsUpdate`) — runs automatically whenever the script is elevated anyway (winget/WSL/npm/`-Sudo`), never triggers elevation by itself and never reboots on its own (`-AutoReboot` handles that). Security: PSResourceGet updates are pinned to the module's original repository and only auto-trust PSGallery or repositories the user marked trusted (was a blanket `-TrustRepository`).
- **v12.21** — New: Cursor extensions section (`cursor --update-extensions`, `-NoCursor`). Perf ([#11](https://github.com/baurfm/update/issues/11)): VS Code/Cursor use the CLI's own `--update-extensions` (one call, outdated extensions only) instead of force-reinstalling every extension each run; old per-extension loop kept as fallback for CLIs without the flag. Fix ([#12](https://github.com/baurfm/update/issues/12)): npm installs `<pkg>@<latest>` for outdated globals instead of `npm update -g`, which never crossed major versions but reported them as updated. Fix ([#13](https://github.com/baurfm/update/issues/13)): modules installed via PSResourceGet (`Install-PSResource`) are now updated too. Fix ([#14](https://github.com/baurfm/update/issues/14)): self-updates (Claude Code, uv, Oh My Posh, pnpm, Bun, Deno, Poetry, Rye, Composer) compare `--version` before/after and no longer count a no-op as "updated". UX: colored "UPDATE" logo banner, per-group colors and emoji icons (Windows Terminal / VS Code terminal only; `UPDATE_NO_EMOJI=1` to disable), progress bar in every section header, bar chart for section timings.
- **v12.20** — Audit fixes. Fix: self-update never re-ran a pulled script update — the version regex looked for a `$_version = "v…"` literal that doesn't exist, so the run always continued with the old in-memory code; now diffs the pulled commit range for `update.ps1`/`update.functions.ps1` (and no longer pulls during `-DryRun`). Fix: `-Only npm,uv` matched nothing when invoked via `pwsh -File` (the `update.cmd` shim, Scheduled Task, elevation re-launch) because it arrives as one literal string `"npm,uv"` — now split on commas (`ConvertTo-OnlyFilter`); the elevation re-launch also passed array values as separate arguments, binding the second one positionally to `-OutputJson`. Fix: a section aborted by an unhandled exception was never recorded as failed — the summary said "No failures" and the run exited 0. Fix: `-RegisterSchedule` ran as SYSTEM, where all per-user tools (Scoop, npm/pnpm globals, pipx, uv, rustup, VS Code extensions, WSL distros) were either not found or updated SYSTEM's own profile — now runs as the registering user (S4U, elevated, no stored password); re-register to apply. Fix: network pre-check used ICMP ping, which many corporate firewalls/VPNs drop (false "offline", exit 5) — now a TCP connect to port 443. Fix: PowerShell module check crashed on prerelease versions (`3.0.0-preview1` isn't a valid `[version]`). Fix: `update.cmd` shim now passes `-NoProfile -ExecutionPolicy Bypass` (the `powershell.exe` fallback failed under the default `Restricted` policy); existing generated shims are refreshed automatically. Fix: winget listing calls pass `--accept-source-agreements` so a fresh profile can't block on a prompt. Fix: `Format-Elapsed` rounded half-to-even (`[int]1.5` = 2), so 90s showed as "2m 30s" and the tlmgr heartbeat jumped backwards ("2m 30s" → "2m 0s") — caught in a live run. Fix: VS Code extensions delisted from the Marketplace ("not found") failed every single run — now reported as skipped with the uninstall command; real failures now log the CLI output. New: Claude Code section (`claude update`, `-NoClaude`). UX: summary lists categories in run order. Chore: script-header and internal version strings were out of sync (12.19 vs 12.18); `PSScriptAnalyzerSettings.psd1` excludes the ~80 by-design warnings (Write-Host etc.) so real ones show up in CI.
- **v12.19** — Fix: a live run inside Windows Terminal had winget upgrade `Microsoft.IntelligentTerminal` (Windows Terminal) itself mid-`--all`, which restarts the ConPTY host and silently killed the elevated `update.ps1` session right after the source refresh — no error, no summary, just back to the prompt, leaving a stale lock behind (already self-healed by the existing dead-PID eviction, but confusing). Now mirrors the existing Git.Git-blocker pattern: when `$env:WT_SESSION` is set (i.e. we're running inside Windows Terminal), Microsoft.IntelligentTerminal is temporarily pinned out of `--all` and reported as skipped instead — run from a classic `powershell.exe`/`cmd.exe` console (or let the Store auto-update it) to actually update it.
- **v12.18** — Three UX improvements aimed at the biggest remaining pain points: (1) commands now echo their raw output live on a genuine final failure, even without `-Verbose` — quiet-on-success stays quiet, but you no longer have to re-run a possibly-long section just to see what broke. (2) The closing summary card adds a `Details: <log path>` line whenever there were failures. (3) Long, silent background-job waits (TeX Live's `tlmgr` run, any `-CmdTimeoutSec`-wrapped command) now print a periodic "still running (Xm elapsed)" heartbeat every 30s instead of going quiet for minutes, which could look like a hang.
- **v12.17** — Extracted the Git.Git pending-update record logic (increment `skipCount`, preserve `firstDetected` across runs) into a pure `Build-PendingGitUpdateRecord` in `update.functions.ps1`, with tests. Evaluated further modularization (full PowerShell module, per-category files) and deliberately held off — not justified for a single-maintainer, single-entry-point tool.
- **v12.16** — Architecture: pure, side-effect-free helpers (winget output parsers, formatting, `-Only` matching) moved into a new dot-sourced `update.functions.ps1`, unlocking a real Pester unit-test suite (`tests/`, run automatically in CI) — no behavior change for end users, still a single `.ps1` to run. This is not a move toward a full PowerShell module; everything else stays in `update.ps1`. Distribution updated accordingly: the Scoop package now installs from the tagged source archive instead of a single uploaded asset (see `scoop-bucket`).
- **v12.15** — UX: winget's own raw output (source refresh + the `--all` upgrade table, previously an intentional exception left as direct passthrough for "long operation, live progress") is now captured and gated behind `-Verbose` like every other section — consistent quiet-by-default behavior across the whole script, per direct feedback that the passthrough looked out of place.
- **v12.14** — Simplification pass: removed the `Write-Status -Type Detail` case, which had become 100% behaviorally identical to `-Type Info` (same gating, same rendering) after earlier refactors — replaced its 3 call sites with `Info`. Merged `Get-WingetUpgradableIds` and `Get-WingetExplicitTargetIds`'s near-identical column-parsing logic into a shared `Get-WingetTableIds` — the duplication had directly caused the v12.10 bug (a fix landing in one copy but not the other). Testing the merge surfaced two more real bugs before they shipped: (1) a generic "line starts with a digit" summary-line check would have misparsed a legitimately digit-led package name like "7-Zip" as a summary line — replaced with matching winget's specific wording; (2) `[Parameter(Mandatory)]` on the new function's array parameter rejected the whole array whenever the winget output's own blank line (a normal, expected element) was present — a lesser-known PowerShell gotcha where mandatory array parameters validate every element, not just the array as a whole. Both fixed and verified against 5 scenarios before merging.
- **v12.13** — Cleanup pass: removed three files that were accidentally tracked in git despite being pure artifacts (`update.cmd` — a runtime-generated shim, `testout.txt` — a stray old debug dump, `.claude/settings.local.json` — personal Claude Code config, now all in `.gitignore`). Fix: `$script:ExitElevationMissing` (exit code 3) was declared and documented in the README but never actually used — the real gap it exposed was that cancelling the UAC prompt during self-elevation had no error handling at all and would crash with a raw Win32Exception; now caught cleanly and exits with the documented code.
- **v12.12** — Systematic test pass over lock handling, dedicated one-shot commands, and notifications turned up three real bugs: (1) `Remove-UpdateCommand`'s PATH-cleanup fallback called `.TrimEnd()` on a caught `$_` inside a `catch` block, where `$_` is the ErrorRecord, not the loop variable it shadowed — threw a real (harmless but ugly) error on every `-RemoveFromPath` run where a PATH entry needed `Resolve-Path` to fall back. (2) `-UnregisterSchedule` (no task present) and `-RemoveFromPath` (nothing to remove) printed no output at all beyond the banner — their sole feedback used `-Type Info`, silently hidden by the v12.5 default-tier chatter filter; switched to `-Type Success`/`-Type Skip` so dedicated one-shot commands always show their outcome. (3) `Write-UpdateEventLog` called `[EventLog]::SourceExists` before checking admin rights, which throws ("Inaccessible logs: Security") rather than just failing gracefully when not elevated — admin is now checked first. Also verified: stale/live lock detection, `-NoLock`, `-Quiet`, PS5.1+PS7 parsing, and a clean PSScriptAnalyzer pass.
- **v12.11** — Repo is now public and published as a Scoop package (`scoop bucket add baurfm https://github.com/baurfm/scoop-bucket && scoop install baurfm/update`), tracking tagged GitHub Releases from here on. Fix: `-Help`/`-h`/`-?` ran through the entire lock/network/self-update/elevation pre-check flow (including a possible UAC prompt) before printing help — moved to the very top of the script so it exits immediately. Added the LICENSE file the README already referenced.
- **v12.10** — Fix: `Get-WingetUpgradableIds` produced garbage entries (e.g. `ble.`, fragments of unrelated text) in the update summary whenever winget printed a second section after the main table (the "require explicit targeting" list, now common since v12.7). Root cause was two-fold: (1) the loop `continue`d past blank lines instead of stopping, reading straight into the next section's free-form text and column-slicing it as if it were a table row; (2) the "skip summary lines like '2 upgrades available.'" check tested the column-sliced fragment for a leading digit instead of the original line, so a slice landing mid-word (`available` → `ble.`) wasn't recognized as a summary line and slipped through. Caught live in production — thanks for flagging the garbled output.
